# Personal Knowledge

Durable personal preferences and working context that are safe and useful across projects.

## What Belongs Here

- Stable communication preferences
- Established working habits
- Accessibility needs
- Tooling constraints
- Repeated design or engineering preferences
- Explicit boundaries for automation

## What Does Not Belong Here

- Passwords, credentials, or authentication details
- Sensitive personal or family information
- Temporary moods or one-time task context
- Guesses inferred from isolated behavior
- Project-specific technical decisions

## Recording Guidance

Each entry should include:

- Preference or constraint
- Scope
- Evidence or explicit request
- Date recorded
- Review trigger, when applicable

Explicit user statements take precedence over inferred preferences.
