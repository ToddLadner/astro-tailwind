# Context Rules

Reusable guidance for keeping work scoped, verified, and transferable.

## Context Intake

- Read files on demand instead of loading the entire repository.
- Verify exact names, paths, and APIs against source files before editing consumers.
- Limit each task to one feature, one bug, one review goal, or one clear migration step.

## Context Use

- For multi-file work, process files in dependency order.
- Verify each completed step before using it as context for the next.
- Create a handoff when switching roles or starting a fresh conversation.

## Handoff

- Include only verified facts, changed files, validation results, open risks, and the next bounded step.
