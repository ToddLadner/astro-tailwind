# Documentation Rules

Reusable guidance for writing and maintaining project documentation.

## Source Of Truth

- Document verified implementation details only.
- Do not describe planned behavior as if it already exists.
- Keep documentation close to the feature, decision, or workflow it explains.

## Style

- Use concise headings and direct language.
- Record decisions, tradeoffs, constraints, and validation outcomes.
- Prefer durable guidance over temporary task narration.

## Maintenance

- Update documentation when behavior, setup, architecture, or project conventions change.
